# 课程预览页 UX 审查

## 1. 页面目标、用户、核心任务、主行动

- **页面类型**：桌面端 Web 课程预览页。
- **目标用户**：正在判断“大模型分布式训练”是否适合自己、并准备开始学习的开发者。
- **页面目标**：帮助用户在进入课程前判断课程是否匹配自己的基础，理解阶段与单元的串联关系，并知道学习后将获得什么可验证结果。
- **核心任务**：确认适配性 → 理解四阶段路线 → 开始阶段 1。
- **主要行动**：`开始阶段 1`。`加入计划`保持为次要行动。

## 2. 当前任务路径

课程入口 → 课程预览 → 判断投入与适配性 → 查看个性化调整 → 理解四阶段及对应单元 → 开始阶段 1／加入计划 → 点击阶段进入单元预览 → 完成讲次与实践 → 阶段 4 验收后回馈社区。

课程总览状态不预选任何左侧阶段。只有用户点击某一阶段后，左侧阶段与右侧单元内容才同步进入选中状态。

## 3. Top 5 UX 问题

| 严重度 | 置信度 | 问题 | 所属层 | 违反原则 | 用户影响 | 修改方向 | 修改收益 |
|---|---|---|---|---|---|---|---|
| P1 | 高 | 个性化调整卡片面积和视觉权重过大，抢占“理解学习路线”的主任务 | 信息架构、视觉 | 渐进披露、任务优先级 | 用户先读解释，再寻找路线，决策节奏被打断 | 压缩为一条辅助信息；保留调整结论、关键补充和查看依据 | 更快进入核心路线，仍保留个性化可信度 |
| P1 | 高 | 四张横向阶段卡同时展开，单元名、原因和结果并列，扫描成本高 | 信息架构 | 认知负荷、渐进披露 | 用户需要逐卡阅读才能理解先后关系 | 改为纵向单线；仅展开阶段 1，后续阶段保留目标、单元和承接关系 | 阶段顺序更直观，单元映射更清楚 |
| P1 | 中 | 左侧阶段与右侧阶段存在重复，但静态界面不能证明切换时是否同步 | 导航、反馈 | 系统一致性、状态可见性 | 用户可能不清楚点击左侧后右侧会发生什么 | 总览不预选；点击后左右同步高亮，并滚动到相应阶段 | 建立目录与内容的一一映射。点击、滚动定位和焦点反馈**需实机验证** |
| P2 | 高 | 同行数据与社区验证被拆成两个同权区域，概念偏抽象 | 信息架构、信任 | 清晰语言、证据邻近 | 用户难以判断这些数字与选课决策的关系 | 合并为“同行与课程可信度”，一句话解释数据用途 | 辅助信息更紧凑，也更能支持决策 |
| P2 | 高 | 社区回馈在学习前已出现可点击动作，时机过早 | 交互、信任 | 防错、用户控制 | 用户可能误以为现在就要发布内容 | 标明“完成阶段 4 后解锁”，验收前只解释价值，不提供可执行主按钮 | 减少压力，避免错误承诺和误操作 |

## 4. 九层 UX 评分

| UX 层 | 评分（5 分） | 结论 |
|---|---:|---|
| 视觉层级 | 4.2 | 主标题、主行动和路线卡层级清楚；建议版进一步降低辅助模块权重。 |
| 信息架构 | 3.8 | 功能已完整，但原稿同时展开的信息过多；纵向单线更符合总览任务。 |
| 交互设计 | 3.7 | 主次按钮合理；阶段联动、禁用态和社区解锁逻辑需补状态。 |
| 导航与可发现性 | 3.6 | 左右都能找到阶段；必须落实总览不选中、进入阶段后同步选中。 |
| 反馈与系统状态 | 3.4 | 静态稿能表达默认态，加载、切换、滚动定位和完成态**需实机验证**。 |
| 表单与错误处理 | 3.0 | 本页不含表单；加入计划失败、学习进度恢复等异常状态**需实机验证**。 |
| 无障碍 | 3.2 | 文字对比度基本合理；键盘焦点、读屏名称、禁用态提示和 200% 缩放**需实机验证**。 |
| 信任与风险 | 4.1 | 调整依据、复现案例与版本信息增强可信度；社区发布应坚持用户确认。 |
| 情感体验 | 3.9 | 路线和同行数据能降低学习不确定性；避免过早出现贡献任务造成压力。 |

## 5. 修改规则

1. 删除课程封面和“上传材料”，页面以低温蓝灰点阵底纹标识课程场景。
2. 总览页只回答五件事：学什么、投入多少、为何适合我、先后怎么走、完成后得到什么。
3. 左侧保留课程身份与阶段目录；总览状态不选中任何阶段。
4. 右侧使用纵向单线，阶段与单元一一映射；默认只展开阶段 1，减少一次性信息量。
5. 个性化调整压缩为辅助条，细节通过“查看调整依据”渐进展开。
6. 同行学习人数、复现案例与适用版本合并为“同行与课程可信度”。
7. 社区回馈在阶段 4 验收后解锁，发布始终由用户确认。
8. 页面只保留一个黑色主按钮“开始阶段 1”，品牌红不作为主要操作色。
9. 阶段切换、键盘焦点、缩放、异常恢复和状态播报需在真实 HTML 中验证。

## 6. 文案替换建议

| 原文案 | 建议文案 | 原因 |
|---|---|---|
| 这门课已经根据你的基础调整 | 已按你的基础调整学习顺序 | 更短，并说明调整对象 |
| 4 个阶段如何串成一条学习路线 | 先完成当前阶段，再进入下一段学习 | 直接告诉用户行动逻辑 |
| 与你目标相似的开发者正在学习／社区验证辅助信息 | 同行与课程可信度 | 合并同类辅助信息 |
| 完成实战后，把验证过的经验回馈社区 | 完成阶段 4 后，可回馈验证经验 | 明确触发条件 |
| 查看共建示例 | 完成实战后解锁 | 避免产生当前可执行的误解 |

修改后的结构保留了课程决策所需的全部信息，同时把页面从“展示所有课程信息”收敛为“帮助用户理解路线并开始第一阶段”。
