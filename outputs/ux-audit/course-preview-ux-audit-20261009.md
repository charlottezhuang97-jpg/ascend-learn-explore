# 课程预览页 UX 审查

审查对象：`course-preview.html?course=training` 桌面 Web 页面  
审查时间：2026-10-09  
审查方式：页面实现、实际渲染截图与交互代码联合检查。

## 1. 页面基础判断

- 页面目标：帮助用户在正式学习前判断课程是否适合自己，并理解课程阶段、学习投入、可信依据与完成成果。
- 目标用户：准备学习昇腾大模型分布式训练的开发者，包含具有单卡训练经验、但对集合通信和多卡训练尚不熟悉的用户。
- 核心任务：确认“为什么学、学什么、按什么顺序学、完成后得到什么”，然后决定是否开始学习或加入计划。
- 主行动：`开始学习`。
- 次要行动：`加入计划`、展开阶段、进入具体单元、查看验证范围、查看相似课程。
- 页面位置：课程发现／AI 生成课程之后，沉浸学习之前的确认层。
- 判断假设：当前页面为桌面 Web 原型；用户尚未开始这门课程。真实数据、登录态、网络失败、学习进度恢复和跨设备持久化仍需实机验证。

## 2. 当前任务路径

```text
进入课程预览
→ 阅读课程目标、投入和适合条件
→ 查看完成成果
→ 通过左侧或中间路线理解 4 个学习阶段
→ 展开阶段并查看对应单元、类型和时长
→ 参考同行学习与课程验证信息
→ 开始学习／加入计划
→ 完成实战后由 AI 整理社区草稿
→ 用户确认后发布
```

主路径总体成立，但存在三个断点：左侧与中间阶段控制的职责重叠；验证信息与当前课程不一致；社区回填只展示流程，没有解释何时可操作以及发布去向。

综合评分：`6.4 / 10`。当前页面已具备完整骨架，但可信信息、双重导航和状态反馈会影响用户是否放心开始学习。

## 5. 修改规则清单

1. 保留一个最高强调操作：`开始学习`；`加入计划`保持描边按钮。
2. 左侧阶段目录只负责定位；中间路线负责阶段展开和单元操作。两个区域共享选中状态，但不重复展示展开内容。
3. 顶部课程目标只讲“学完能完成什么”；成果卡只列具体产出，不重复标题。
4. 每个阶段默认展示“阶段目标 + 单元范围”；展开后再显示递进原因、单元类型、时长和开始入口。
5. 验证信息必须由当前课程数据动态生成，至少包含验证对象、环境／版本、时间和案例入口。
6. 同行进度统一标注口径，例如“课程进度”；头像失败时使用稳定占位，不显示残缺图像。
7. 没有功能的图标按钮必须删除；有功能的图标按钮需要可访问名称、hover、focus、pressed 和关闭机制。
8. 社区回填明确解锁条件、默认可见范围、可编辑状态和最终回填知识节点；完成实战前保持预告态。
9. 加入计划需增加保存中、保存成功、保存失败与重试状态；状态需要持久化，重新进入页面仍可识别。
10. 单元入口点击热区建议至少 40×40px；12px 辅助文字需要进行 WCAG 对比度实测。
11. 移动端隐藏左侧目录后，需要提供可访问的阶段定位方式，不能只依赖中间长列表。
12. 首页推荐、AI 生成、测验完成和课程列表进入该页时，应保留来源上下文与返回位置。

## 建议标注点清单

1. 顶部课程目标与成果卡标题重复。
2. 左侧阶段目录与中间阶段卡存在重复展开逻辑。
3. 当前阶段的“为何进入下一阶段”文案层级过弱。
4. 单元播放按钮热区偏小，只有图标，没有可见文字。
5. 同行百分比缺少“课程进度”口径。
6. 第二、第三位同行头像未正确呈现。
7. 同行卡右上“···”没有功能。
8. 课程验证文案与分布式训练课程不匹配。
9. 课程验证缺少环境、版本、日期和统计口径。
10. 社区回填缺少解锁条件、默认隐私和发布去向。

## 一句话总结

页面已经能说明课程结构，但需要把重复导航收敛为“一处定位、一处操作”，并用与当前课程一致、可核验的证据支撑用户开始学习的决定。
