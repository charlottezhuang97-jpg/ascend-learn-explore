# 课程路线、同行学习与个人知识地图 UX 审查

## 1. 页面基础判断

### 课程路线与同行学习

- **页面类型**：桌面 Web 课程预览中的路线总览模块。
- **推测目标用户**：正在判断课程结构、学习顺序与可信度的开发者。
- **用户核心任务**：理解四阶段关系，确认课程值得学，并进入阶段 1。
- **当前页面主行动**：开始阶段 1；当前截图未呈现，假设由课程预览页上层主操作承载。
- **平台假设**：桌面 Web，大屏优先。
- **5 秒理解度**：能看出四阶段路线，但阶段之间为什么承接、同行卡是否可操作仍不够明确。

### 个人知识地图

- **页面类型**：AI 学伴中的可缩放个人知识地图中心。
- **推测目标用户**：希望了解当前位置、已掌握知识和下一步方向的学习者。
- **用户核心任务**：定位当前课程，理解相邻领域，缩放或下钻查看知识点。
- **当前页面主行动**：进入当前课程所在板块“模型训练／分布式训练”。
- **平台假设**：桌面 Web 无限画布。
- **5 秒理解度**：能感知“我在中心、领域围绕我”，但地图状态、点击对象和缩放后显示层级不够明确。

**一句话结论**：概念和视觉方向成立，但目前更像概念海报；标题与 2.5D 资产占比过高，真实产品所需的信息密度、状态表达和操作可发现性不足。

## 2. 用户任务路径分析

### 课程路线与同行学习

1. 用户看到路线大标题和四个 2.5D 阶段。
2. 沿连接线理解先后顺序。
3. 查看阶段名称、对应单元和阶段间说明。
4. 向下查看相似用户正在学习什么。
5. 查看课程是否经过真实案例和版本验证。
6. 返回课程页主行动，开始阶段 1。

当前断点：阶段卡与用户卡的点击结果不明确；同行信息与“是否适合我”的决策联系较弱。

### 个人知识地图

1. 用户看到自己位于地图中心。
2. 通过“当前课程”定位到模型训练板块。
3. 浏览相邻领域和连接关系。
4. 使用滚轮、加减按钮缩放，或拖拽画布移动。
5. 点击板块下钻到知识点，使用面包屑返回。
6. 进入当前课程或选择下一探索方向。

缩放、拖拽、板块选中、返回和焦点反馈均**需实机验证**。

## 3. 最重要的 5 个问题

| 问题 | 严重程度 | 位置 | 影响 | 参考原则 / 来源类型 | 修改建议 |
|---|---|---|---|---|---|
| 1. 页面与模块标题过大 | P1，高置信 | 两张图左上标题、课程路线模块标题 | 标题消耗过多纵向空间，用户首屏看到的可操作信息减少；知识地图标题与地图主体争夺焦点 | 视觉层级、极简美学原则（权威启发式参考） | 页面 H1 收敛至 28px/36px Medium，模块标题 20px/28px Medium，卡片标题 16px/24px；标题区上下间距控制在 16–24px |
| 2. 2.5D 视觉资产过大且同权 | P1，高置信 | 四阶段图标、五块知识岛 | 图标成为主角，阶段成果、状态和下一步退居次要；所有板块同样明亮，难以判断当前位置 | 视觉焦点、Aesthetic and Minimalist Design（权威启发式原则） | 路线图标缩小 15%–20%；知识地图只强化当前板块，邻近板块降低饱和度和细节级别 |
| 3. 路线“相连”但承接结果仍不具体 | P1，高置信 | 课程路线阶段之间 | 用户知道顺序，却不知道上一阶段产出什么、为何足以进入下一阶段 | 符合现实世界、识别优于回忆、渐进披露（权威参考） | 将连线上的说明改为“阶段成果 → 下一阶段用途”，例如“输出并行策略 → 用于配置设备通信” |
| 4. 知识地图缺少语义缩放与状态图例 | P1，中置信 | 地图节点、缩放控件、板块标签 | 48% 缩放时文字已经偏小；继续缩放后可能造成信息拥挤，用户也无法区分已掌握、正在学习、待探索 | 系统状态可见、WCAG 状态可感知（官方标准／启发式原则） | 建立三级语义缩放；补充状态图例，并通过形状＋文字表达状态，避免只依赖蓝色。真实缩放行为需实机验证 |
| 5. 同行与验证信息的用途、边界不清楚 | P2，高置信 | 用户卡、“这些内容经过实际验证” | 用户不知道同行卡能否点击；“12 个案例”缺少范围，头像与学习状态还涉及数据授权和隐私预期 | 清晰语言、透明性、用户控制（官方指南／权威原则） | 标明“查看他公开的学习路径”或将卡片设为纯展示；增加“数据来自公开学习动态”；验证信息提供范围与更新时间入口 |

## 4. 9 大 UX 层面评分

| UX 层面 | 课程路线 / 5 | 知识地图 / 5 | 关键结论 | 建议 |
|---|---:|---:|---|---|
| 视觉层面 | 3.6 | 3.7 | 质感统一，但标题与 2.5D 元素尺度过大 | 缩小标题和视觉资产，增加正文与状态密度 |
| 信息层面 | 3.7 | 3.3 | 路线有顺序，地图有领域；阶段成果和地图层级仍不够明确 | 增加成果承接、语义缩放和状态图例 |
| 交互层面 | 3.2 | 3.1 | 卡片、岛屿、节点是否可点不完全可辨 | 统一可点击样式；hover、pressed、selected 需实机验证 |
| 流程导航层面 | 3.6 | 3.8 | 路线顺序和地图面包屑存在 | 补充阶段入口结果；地图下钻后保持父级和邻域上下文 |
| 反馈状态层面 | 3.1 | 3.0 | 静态图缺少加载、切换、缩放和完成反馈 | loading、选中、缩放边界、定位反馈需实机验证 |
| 表单与错误层面 | 3.0 | 3.0 | 当前无表单 | 地图加载失败、头像编辑失败、数据为空状态需实机验证 |
| 无障碍层面 | 3.1 | 2.9 | 小字与浅蓝文字在缩放后风险更高；复杂手势需替代入口 | 保留加减按钮与适应画布；键盘、焦点、读屏语义需实机验证 |
| 信任与风险层面 | 3.3 | 3.6 | 同行头像和学习状态需要解释数据来源；地图个人进度相对清楚 | 说明公开范围、更新时间和数据使用方式 |
| 情绪体验层面 | 4.2 | 4.3 | 2.5D 形式具有探索感和学习成就感 | 收敛装饰密度，保持轻松但不游戏化 |

- **课程路线整体评分**：72/100，体验等级：可用但需优化。
- **知识地图整体评分**：73/100，体验等级：可用但需优化。

## 5. 修改规则清单

| 编号 | 修改规则 |
|---|---|
| 1 | 统一压缩字号：页面 H1 28/36 Medium、模块标题 20/28 Medium、卡片标题 16/24 Medium、正文 14/22 Regular、辅助信息 12/18 Regular；保留 HarmonyOS Sans 和现有字重倾向。 |
| 2 | 课程路线整体高度压缩约 20%；缩小图标和底座，不取消 2.5D 形式与四阶段连接关系。 |
| 3 | 阶段连线只承载“上一阶段成果 → 下一阶段用途”，不继续添加长说明卡。 |
| 4 | 同行卡保留真实感头像与 ID，但每卡只展示头像、ID、当前课程和进度；明确卡片是公开路径入口还是纯展示。 |
| 5 | 将“这些内容经过实际验证”保留为用户语言，补充“验证范围”和“最近验证时间”；不恢复“验证依据”等内部术语。 |
| 6 | 知识地图采用语义缩放：全局只看五大领域，中层看模块，近景才看知识点；不在 48% 视图同时展示所有小节点。 |
| 7 | 中央头像缩小并避开主要连接线；保留“编辑我的形象”，弱化为次要入口。 |
| 8 | 当前板块、已掌握、待探索分别使用图形、文字和颜色三重状态；不只依赖蓝色深浅。 |
| 9 | 缩放控件、适应画布和小地图保持固定屏幕尺寸，不跟随画布缩放。 |
| 10 | 不增加新的主按钮；课程页主行动仍由“开始阶段 1”承载，知识地图主行动是进入当前课程板块。 |

| 原文案 | 推荐文案 |

| 4 个阶段对应 6 个单元，完成上一阶段的成果，才会解锁下一段能力。 | 6 个单元分成 4 个阶段；每一步都会产出下一阶段需要的成果。 |

## 建议标注点清单

### 课程路线与同行学习

1. 标题区：H1 缩小至 28px，副标题与标题间距 8px。
2. 路线区：四个 2.5D 图标及底座缩小 15%–20%。
3. 连线区：把抽象说明替换为“产出 → 用途”。
4. 阶段卡：减少编号、箭头与标题的重复强调。
5. 同行区：标题缩小至 20px；卡片高度压缩，明确整卡是否可点。
6. 可信度区：补“查看验证范围”，解释案例与版本数据。

### 个人知识地图

1. 页面标题：由展示型大标题降至 28px 产品标题。
2. 中央头像：缩小并向下错开，避免遮挡模型训练连接线。
3. 当前领域：保留高对比；相邻领域降低约一级饱和度。
4. 节点标签：48% 仅显示领域名；模块与知识点按缩放级别出现。
5. 左侧概览：压缩卡片高度，减少图标占比。
6. 地图状态：补充“已掌握／正在学习／待探索”图例。
7. 缩放与小地图：固定于视口，不随画布内容缩放。

## 7. 一句话总结

当前最需要优先优化的是标题和 2.5D 资产的尺寸，以及地图的语义缩放；它们直接决定用户能否在保留立体视觉特色的同时，快速看懂路线、当前位置和下一步行动。
