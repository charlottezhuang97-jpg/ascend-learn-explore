# 场景模式层

场景模式定义页面级布局、信息顺序和跨组件关系。它们不是单个组件的集合，而是用户完成一类任务时的稳定工作区。

## 模式目录

| 模式 | 页面入口 | 核心任务 | 布局特征 |
| --- | --- | --- | --- |
| `home-discovery` | `index.html` | 表达目标、发现开发场景、发现榜样 | Hero 搜索 → 场景路线 → 公共成长榜 |
| `ai-dialogue` | 首页搜索后 | 补齐目标、生成路径和课程 | 连续步骤流，不使用大步骤卡片 |
| `course-preview` | 首页课程卡、课程列表课程卡 / AI 生成完成后 | 判断是否适合并开始学习 | 课程成果、知识路线、成本、底部操作栏 |
| `whiteboard-learning` | `learn.html` 默认视图 | 通过板书和字幕理解概念 | 讲课画布 + 右侧 AI 学伴 |
| `video-workbench` | `learn.html` 切换视频 | 边看视频边查看代码并实践 | 视频 + 代码 + 可收起 IDE，支持拖动调宽 |
| `growth-feedback` | 首页成长榜、个人空间、AI 学伴 | 看到成果并获得下一步行动 | 公共榜单摘要与个人证据记录分离 |

## 模式合同

每个模式都必须定义：

1. 用户进入条件和退出方式；
2. 默认信息顺序；
3. 主要区域与辅助区域；
4. 关键交互和键盘路径；
5. 加载、完成、失败和恢复状态；
6. 与其他页面的数据连接；
7. 不应放入该模式的信息。

## 复杂布局规则

- 画布、视频工作台和 IDE 不重复套用普通卡片容器；
- 工作台的分隔条必须支持鼠标和键盘调整；
- 全屏流程必须使用统一最高层级，不能被首页 Hero、快捷菜单或导航穿透；
- 模式内部的标题、工具和状态保持固定位置，异步内容只替换内容区，避免页面跳动。

## Pattern 文件合同

每个模式文件必须包含“用户任务、进入／退出、区域结构、组件组合、状态、交互序列、数据连接、排除内容和验收点”八个部分。模式文件描述的是可以被多个页面复用的工作区合同，不写某一次演示数据。

| Pattern | 必须稳定的区域 | 必须联动的数据 |
| --- | --- | --- |
| `home-discovery` | 搜索、开发场景、课程发现、成长榜 | 用户目标、场景筛选、课程摘要、公共榜单 |
| `ai-dialogue` | 用户问题、四步生成流、回答内容、返回入口 | 目标画像、来源、答案、大纲、生成状态 |
| `whiteboard-learning` | 顶部工具、板书画布、字幕、AI 学伴 | 课节、页码、字幕、笔记、问答上下文 |
| `video-workbench` | 视频、代码、IDE、资源 Tab、拖动分隔条 | 播放时间、代码片段、运行结果、学习进度 |
| `course-preview` | 目标、成果、目录、成本、操作栏 | 课程版本、来源、环境、学习计划 |
