# 学习方案设计系统

这是学习方案探索版的设计系统入口。它把页面还原规则拆成五层，并规定每层解决什么问题：

```text
Token → 组件 → 场景模式 → 状态 → 验收
```

页面实现必须先复用已有 Token、组件和场景模式；只有现有系统无法表达需求时，才进入预览和审批流程。视觉值、页面结构和交互状态不能在业务页面中私自形成另一套规则。

## 五层结构

| 层级 | 文件 | 负责内容 |
| --- | --- | --- |
| Token | `tokens/foundation.json`、`tokens/semantic.json`、`tokens/components.json` | 基础值、页面语义和组件级规格 |
| 组件 | `components/README.md` | 按钮、输入框、标签、卡片、步骤、代码片段和面板 |
| 场景模式 | `patterns/README.md` | 首页、AI 对话、课程预览、白板学习、视频工作台和成长反馈 |
| 状态 | `states.md` | 加载、进行中、成功、失败、完成、选中、收起和恢复 |
| 验收 | `acceptance.md` | 视觉、交互、层级、可访问性和响应式检查 |

## 决策优先级

1. 用户确认的最新设计稿和交互决策；
2. 场景模式中的布局和状态约束；
3. 组件规格；
4. 语义 Token；
5. 基础 Token。

当规则发生冲突时，记录冲突原因和最终决定，不在页面 CSS 中静默覆盖。

## 表面类型

学习方案不是单一页面皮肤，而是三个有不同信息密度的表面：

- **发现表面**：首页、资源列表和课程卡，使用浅色内容优先布局，帮助用户判断角色、场景和学习起点。
- **AI 对话表面**：学习目标确认、构思学习路径、课程大纲和课程生成，使用连续信息流和逐步披露。
- **沉浸学习表面**：白板和视频工作台，使用稳定的内容区域、工具区和辅助面板，强调学习过程与实践操作。

## 新增样式的门禁

如果已有组件和场景模式无法满足需求，先创建预览，至少展示现有方案、新方案、normal/hover/active/selected 状态、Token 使用和新增原因。得到用户明确确认后，先把新模式吸收到本设计系统，再由具体页面使用。

## 兼容文件

- `../design.md`：标题字体和历史设计背景入口，详细规则已拆到本目录。
- `tokens/design-tokens.json`：旧页面使用的 Figma 导出兼容文件；新页面以本目录的三层 Token 为准。
- `../docs/前端还原规范.md`：前端实现与交付入口，负责引用本目录并记录页面级例外。
